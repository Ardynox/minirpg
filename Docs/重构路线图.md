# MiniRPG 重构路线图

这份文档记录当前目标结构、重构批次和完成标准。

## 目标结构

- `App/Main*.cs` 只保留 Godot 生命周期入口和组合根装配，运行时编排全部下沉到 `App/RuntimeUi/*`。
- `GameSessionModule` 收敛为纯会话编排层，目录管理、继续游戏、backend 细节分别由 `WorldCatalogService`、`ContinueStateService`、`MiniRPG.Shared/Module/Session/*` 承担。
- `ServerActionGateway` 保留统一入口，具体 handler/service 持续外提。
- `IsometricVoxelRenderer` 继续拆分渲染 pass、模式切换和性能记录。

## 当前批次

### 批次 1：Main 瘦身（进行中）

- 把 `Main.*.cs` 中的运行时编排逻辑迁移到 `App/RuntimeUi/*` 协调器。
- 完成标准：`Main` 只保留节点获取、组合根装配和薄委托，不再包含业务判断。

### 批次 2：会话层收敛

- `GameSessionModule` 不再直接操作目录、文件系统或 backend 细节。
- 完成标准：`GameSessionModule` 只编排会话生命周期，所有细节由下层服务处理。

### 批次 3：指令层外提

- `ServerActionGateway` 中的具体保留策略、奖励、容器等逻辑外提到专门服务。
- 完成标准：`ServerActionGateway.Execute` 只做分发，不包含领域规则。

### 批次 4：渲染层拆分

- `IsometricVoxelRenderer` 拆分渲染 pass、光照计算、模式切换和性能记录。
- `VoxelLightingCalculator` 已独立，后续继续拆分其他职责。
- 完成标准：单个渲染类不超过 1500 行。

## 已完成

- `TileMapRenderModule` 职责已合并到 `IsometricVoxelRenderer`。
- `VoxelLightingCalculator` 从 `IsometricVoxelRenderer` 独立。
- `WeatherFxController` 从渲染总控中抽出。
- `WorldCatalogService`、`ContinueStateService` 从 `GameSessionModule` 抽出。
- `ReservationService`、`LootService` 从 `ServerActionGateway` 抽出。
- `TimelineTurnGateway` 独立为玩家动作推进入口。
- `GameEventPresentationRouter` 承接 `GameEvent -> UI/FX/日志` 翻译。
- `MainStartupCoordinator`、`MainInputCoordinator`、`MainAppFlowCoordinator`、`GameplayCommandCoordinator` 等协调器已从 `Main` 抽出。
