# MiniRPG 重构路线图

这份文档记录当前目标结构、重构批次和完成标准。

## 协作意图

- Main 的方向是**只保留 Godot 生命周期、节点获取、组合根装配和薄委托**，每轮拆掉"散落在 `Main.*.cs` 里的业务判断"，逐步把业务下沉到 `App/RuntimeUi/*` 和 `MiniRPG.Shared/Module/*`。
- 每轮优先挑**范围小、可独立编译、能过完整 `dotnet test`** 的切入点，不在一次改动里同时动多块业务。
- 拆出去的新类默认放在：客户端运行时编排 → `App/RuntimeUi/`；领域/会话/协议翻译 → `MiniRPG.Shared/Module/*`。
- 新增类只在**稳定边界发生变化时**才同步 `Docs/架构现状.md`（"稳定边界"或"修改时先看哪里"段），不追求铺满文档。
- 继续沿用触发式 README：只在某个目录反复成为高上下文热点时才新增局部 `README`。

## 目标结构

- `App/Main*.cs` 只保留 Godot 生命周期入口和组合根装配，运行时编排全部下沉到 `App/RuntimeUi/*`。
- `GameSessionModule` 收敛为纯会话编排层，目录管理、继续游戏、backend 细节分别由 `WorldCatalogService`、`ContinueStateService`、`MiniRPG.Shared/Module/Session/*` 承担。
- `ServerActionGateway` 保留统一入口，具体 handler/service 持续外提。
- `IsometricVoxelRenderer` 继续拆分渲染 pass、模式切换和性能记录。

### 批次 2：会话层收敛

- `GameSessionModule` 不再直接操作目录、文件系统或 backend 细节。
- 完成标准：`GameSessionModule` 只编排会话生命周期，所有细节由下层服务处理。
- 现状：`MiniRPG.Shared/Module/GameSessionModule.cs` 仍有 965 行，距离"纯编排层"还有距离。
- 下一步候选：
  - 把 `GameSessionModule` 里直接读写存档目录的代码继续外提到 `WorldCatalogService` / `ContinueStateService` 下适当的服务。
  - 把 `LocalSessionBackend` 与 `GameSessionModule` 之间共享的会话状态数据，收敛成显式的 `GameSessionState` / `Snapshot` 记录，避免 backend 直接反射会话实现细节。

### 批次 3：指令层外提

- `ServerActionGateway` 中的具体保留策略、奖励、容器等逻辑外提到专门服务。
- 完成标准：`ServerActionGateway.Execute` 只做分发，不包含领域规则。
- 现状：`MiniRPG.Shared/Module/ServerActionGateway.cs` 583 行，已经把 `ReservationService`、`LootService` 抽出；剩余 handler 里还有直接操作 `GameState` 的领域规则。
- 下一步候选：

  - 每抽出一组 handler 同步补一条 `Docs/架构现状.md::指令与玩法执行` 段里的事实。
