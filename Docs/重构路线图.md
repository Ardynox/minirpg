# MiniRPG 重构路线图

这份文档记录当前目标结构、批次顺序和完成标准。
它只写“接下来要收敛到哪里”，不重复展开当前实现细节。

## 目标结构

- `Main` 保持 Godot 入口和组合根角色，不再扩张成全能运行时脚本。
- `App/RuntimeUi/*` 负责启动、输入、应用流程、多人联机流程、事件呈现和运行时视图。
- `GameSessionModule` 只保留会话编排；目录、继续状态、backend 和楼层切换等职责继续外提。
- `ServerActionGateway` 保留统一入口；保留策略、奖励、容器、交易、对话等逻辑落到专门 handler/service。
- `TileMapRenderModule` 保留渲染组合入口；具体 pass、天气特效、模式切换和性能记录拆到独立类。

## 批次顺序

### 批次 1：继续削薄 `Main`

- 目标：
  - 新增运行时编排优先放进 `App/RuntimeUi/*`。
  - 把事件呈现、输入分流、多人联机流程继续从 `Main` partial 中移出。
- 完成标准：
  - `Main` 主要承担场景节点装配、生命周期和薄委托。
  - 新功能不再默认回到 `Main` 里接大段流程代码。

### 批次 2：收敛会话边界

- 目标：
  - 稳定 `WorldCatalogService`、`ContinueStateService`、`Module/Session/*` 的职责。
  - 让 `GameSessionModule` 明确成为“会话编排层”，而不是目录、存储、继续状态、backend、楼层逻辑的混合体。
- 完成标准：
  - 世界目录、继续目标、backend 选择都有明确 owner。
  - `GameSessionModule` 的公开接口以会话动作和编排为主。

### 批次 3：收敛服务端指令执行边界

- 目标：
  - 保留 `ServerActionGateway.Execute` 作为入口。
  - 把容器、保留、奖励、交易、对话、战斗等具体逻辑继续拆到 handler/service。
- 完成标准：
  - `ServerActionGateway` 以路由、参数校验和结果汇总为主。
  - 新增指令优先落到专门 handler，而不是继续堆进网关。

### 批次 4：收敛渲染边界

- 目标：
  - 让 `TileMapRenderModule` 更像渲染组合器，而不是所有渲染实现细节的聚合地。
  - 继续外提天气特效、sprite pass、模式切换、性能记录和编辑态逻辑。
- 完成标准：
  - 渲染改动首先命中专门 helper/pass/controller。
  - `TileMapRenderModule` 不再承担越来越多彼此独立的实现细节。

### 批次 5：文档同步与验收

- 目标：
  - 每完成一个批次，就把新边界写回 `Docs/`。
  - 不再回到日期型审计文或全量扫描文。
- 完成标准：
  - 新人只读这套文档，也能回答“当前结构是什么、下一步改哪里、怎样验证”。

## 临时兼容规则

- 允许通过薄接口或 adapter 暂时隔离旧边界，例如 `IDebugSessionActions` 这类边界接口。
- 允许阶段性保留组合入口，但不允许把已经拆出的职责再回塞进去。
- 重构以“改变职责边界”为主，不做没有收益的大规模命名迁移。
- 每个批次只推进一个主要热点，避免一次同时推倒入口、会话、渲染三条线。

## 每批都要过的验证

- `dotnet build mini-rpg.sln`
- `dotnet test Tests\MiniRPG.Tests\MiniRPG.Tests.csproj`
- 如果改到会话、存档或多人 backend，再补相关定向测试
- 如果改到渲染，再补渲染相关定向测试
- 手动走一遍：主菜单 -> 新游戏/继续游戏 -> 关键 UI -> AutoTest 入口

## 文档同步规则

- 边界稳定后再写入 [`架构现状.md`](./架构现状.md)，不要先按旧结构重写一版再推翻。
- 命令、脚本、验收方式变化时同步更新 [`运行与测试.md`](./运行与测试.md)。
- 默认策略变化时同步更新 [`开发约定.md`](./开发约定.md)。
