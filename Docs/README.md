# MiniRPG 文档入口

AI 或新协作者先读根目录 [`../AGENTS.md`](../AGENTS.md)。
`Docs/` 现在只保留长期维护、直接服务开发和重构的文档。
一次性扫描、日期型审计、全量接口展开稿、占位系统文档不再进入这里。
复杂模块自己的短 `README` 是第二层入口，不计入 `Docs/` 主文档数量。
局部 `README` 采用触发式维护，只给反复成为高上下文热点的目录补，不追求铺满仓库。

## 文档分工

| 文档 | 回答的问题 | 什么时候更新 |
| --- | --- | --- |
| `README.md` | 文档该从哪里读、什么内容该写进 `Docs/` | 文档结构变化时 |
| `开发约定.md` | 团队默认决策、非目标、文档产出规则、协作纪律 | 默认策略或协作约束变化时 |
| `架构现状.md` | 当前稳定边界、主入口、主流程、状态所有权 | 入口、边界、主流程变化时 |
| `重构路线图.md` | 目标结构、重构批次、完成标准 | 重构优先级或目标结构变化时 |
| `运行与测试.md` | 构建、测试、AutoTest、导出与手动冒烟流程 | 命令、脚本或验收口径变化时 |
| `会话生命周期.md` | 会话切换时的清理契约 | 会话切换入口或清理职责边界变化时 |
| `多人联机契约.md` | 单机 / 多人 / 预测三路径的权威边界 | 提交路径或预测对账逻辑变化时 |
| `涌现世界路线图.md` | 从 Utility AI 基线推进到"世界自己长事件"的下一步 | AI 系统目标或第二层落点变化时 |
| `界面与面板.md` | 每个面板做什么、显示哪些字段、操作与数据源、默认快捷键 | 新增 / 删除面板、改主要展示字段、改触发方式或默认快捷键、改 HUD 抑制规则时 |

## 不再放进 `Docs/` 的内容

- 日期型扫描或审计文，例如 `*_AUDIT_*`、`*_SCAN_*`
- 全量 public API、调用链、目录树展开稿
- “未经设计仅供占位”的玩法文档
- 只对当前分支或当前 PR 有价值的调查报告
- 纯堆积问题但没有收敛边界的 `TODO` 文档

## 临时产出放哪里

- 一次性分析、对比、巡检报告：`Artifacts/`
- `Artifacts/README.md` 只说明这个目录为什么默认不该被读
- 改动说明、风险、迁移备注：PR 描述或提交说明
- 资源、工具、数据或复杂模块的局部说明：各自目录下的 `README`

## AI 文档产出规则

- 生成“决策支持文档”，不是“仓库全量扫描结果”。
- 只写稳定问题的答案，不把临时调查当成长期文档。
- 保留高频入口和稳定边界，不展开所有类型、所有调用链、所有目录。
- AI 草稿必须人工删减，判断标准只有一个：下次改代码时还值不值得读。
