# MiniRPG 开发约定

这份文档定义团队默认决策、非目标和文档维护规则。
它不负责枚举当前所有实现细节；当前代码边界请看 [`架构现状.md`](./架构现状.md)。

## 当前目标

- 继续在现有 Godot/C# 工程上增量演进，而不是重造一套通用框架。
- 把运行时编排从 `App/Main*.cs` 逐步收敛到 `App/RuntimeUi/*` 协调器。
- 把会话、服务端指令和渲染胖模块持续拆薄，但不为了“看起来整洁”引入新框架。

## 默认决策

### 增量优先

- 先复用现有入口和现有边界，再考虑新增抽象。
- 新功能默认先找这些入口是否已经有落点：
  - `App/Main*.cs` 与 `App/RuntimeUi/*`
  - `MiniRPG.Shared/Module/*`
  - `MiniRPG.Shared/Core/*`
  - `Module/Panel/*`
  - `Module/Render/*`

### 现有边界优先

- `Main` 是 Godot 入口和组合根，不再继续膨胀成全能脚本。
- `App/RuntimeUi/*` 是运行时编排层，负责启动、输入、流程协调、多人联机协调和事件呈现。
- `GameSessionModule` 是会话编排层；目录管理、继续游戏和 backend 细节分别下沉到 `WorldCatalogService`、`ContinueStateService`、`MiniRPG.Shared/Module/Session/*`。
- `ServerActionGateway` 保留统一入口，但具体保留策略、奖励、容器等逻辑应落在专门服务中。
- `TileMapRenderModule` 是当前渲染组合入口；天气特效、模式切换、性能记录和具体 pass 应继续外提。

### 状态所有权

- `GameState` 是唯一运行时事实源。
- 世界格子与 chunk 数据属于 `WorldMap` / `ChunkData` 一侧。
- `Actor` 真相在运行时状态中维护，不把 UI 缓存当成玩法真相。
- UI、面板、协调器可以缓存显示状态，但必须有明确失效时机。

### 默认不做

- 不引入 ECS、通用状态机框架或新的运行时总线来替代现有结构。
- 不为了文档整齐去生成大而全的扫描文。
- 不把“历史上写过的设计草稿”当成当前事实。

### AI 行为配置

- 所有 NPC 行为通过 `Data/Config/utility_actions.json` 数据驱动，不在 C# 中硬编码行为优先级。
- 新增行为：在 JSON 中添加 `UtilityActionDef`，在 `ExecutorRegistry` 注册对应 `IUtilityExecutor`，在 `InputResolver` 注册所需输入源。
- 调参：修改 JSON 中的 `bonusScore` 和 `Consideration.Curve` 参数，不需要重新编译。
- 性格偏移：在 `Data/Config/personality_defaults.json` 中按种族/职业配置。

## 文档规则

- `Docs/` 只保留这五份长期文档。
- 文件名必须稳定，不使用日期命名。
- 一个文档只回答一个稳定问题。
- 一次性调查、扫描、对比、实验结果写到 `Artifacts/` 或 PR 描述，不写进 `Docs/`。
- 如果改动影响以下内容，必须同步更新对应文档：
  - 默认策略变化：`开发约定.md`
  - 边界、入口、主流程变化：`架构现状.md`
  - 重构批次、目标结构变化：`重构路线图.md`
  - 构建、测试、脚本、导出流程变化：`运行与测试.md`

## AI 产出约束

- 推荐使用这类提示词骨架：

```text
基于当前仓库事实更新文档。
只产出长期维护、面向决策的文档。
不要生成日期型审计、全量 public API、全量调用链、占位系统文。
只保留稳定边界、高频入口、当前重构目标和必要的验证方式。
```

- 生成后必须人工裁剪。
- 只要一份文档不能帮助“快速定位、做决定、避免误改”，就不应该留下。

## 编码与本地化门禁

- 受控文本文件统一使用 UTF-8。
- Python 读写文本显式使用 `encoding="utf-8"`。
- PowerShell 写文本显式指定 UTF-8 编码。
- 涉及中文文本、本地化数据或目录时，提交前至少执行：
  - `python Tools\validate_i18n.py`
  - `dotnet test Tests\MiniRPG.Tests\MiniRPG.Tests.csproj --filter LocalizationCatalogTests`
