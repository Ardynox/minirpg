# MiniRPG 运行与测试

这份文档只保留当前常用、可执行的构建、测试、AutoTest 和导出方式。

## 环境

- .NET 8 SDK
- Godot Mono Windows 版本
- 仓库根目录：`D:\Godot\mini-rpg`

## 常用命令

### 全量构建

```powershell
dotnet build mini-rpg.sln
```

### 全量测试

```powershell
dotnet test Tests\MiniRPG.Tests\MiniRPG.Tests.csproj
```

### 定向测试示例

会话/存档相关：

```powershell
dotnet test Tests\MiniRPG.Tests\MiniRPG.Tests.csproj --filter "FullyQualifiedName~GameSessionModuleTests|FullyQualifiedName~SaveModule"
```

多人联机相关：

```powershell
dotnet test Tests\MiniRPG.Tests\MiniRPG.Tests.csproj --filter "FullyQualifiedName~Multiplayer"
```

渲染相关：

```powershell
dotnet test Tests\MiniRPG.Tests\MiniRPG.Tests.csproj --filter "FullyQualifiedName~Render"
```

本地化相关：

```powershell
python Tools\validate_i18n.py
dotnet test Tests\MiniRPG.Tests\MiniRPG.Tests.csproj --filter LocalizationCatalogTests
```

美术资源路径（`Data` 内 `res://Assets/Art/...` 与 `res://Assets/Faces/...` 是否落盘；可选扫描 `resource_catalog` + `combat_fx` 与 catalog 对齐检查）：

```powershell
python Tools\validate_art_res_paths.py
python Tools\validate_art_res_paths.py --catalog --combat-audit
python Tools\validate_art_res_paths.py --no-faces
```

最后一行：仅校验实体渲染 / 物品世界 / catalog，不扫 `Data/FaceParts`（例如正在批量改脸图时）。

## 运行项目

### 在 Godot 中打开

- 直接用 Godot 打开仓库根目录。
- 启动入口场景是 `App/Main.tscn`。

### 命令行启动

```powershell
godot --path D:\Godot\mini-rpg
```

## AutoTest

### 游戏内入口

- 主菜单按钮：`自动化测试`
- 适合需要真实 UI / 会话状态的巡检

### 包装脚本

```powershell
.\Tools\run_autotest.ps1 -GodotExe D:\Godot\godot\bin\godot.windows.editor.x86_64.mono.exe
.\Tools\run_autotest.ps1 -GodotExe D:\Godot\godot\bin\godot.windows.editor.x86_64.mono.exe -Headless
.\Tools\run_autotest.ps1 -GodotExe D:\Godot\godot\bin\godot.windows.editor.x86_64.mono.exe -Headless -Scenarios resource_smoke -StepDelay 0
```

### 直接传 CLI 参数

```powershell
godot --headless --path D:\Godot\mini-rpg -- --autotest
godot --headless --path D:\Godot\mini-rpg -- --autotest --autotest-scenarios resource_smoke --autotest-step-delay 0
```

## 导出与打包

标准脚本：

```powershell
powershell -ExecutionPolicy Bypass -File ".\Tools\export_and_package_lan.ps1"
```

常用参数：

```powershell
powershell -ExecutionPolicy Bypass -File ".\Tools\export_and_package_lan.ps1" -GodotBinDir "D:\Godot\godot\bin"
powershell -ExecutionPolicy Bypass -File ".\Tools\export_and_package_lan.ps1" -GodotExe "D:\Godot\godot\bin\godot.windows.editor.x86_64.mono.exe"
powershell -ExecutionPolicy Bypass -File ".\Tools\export_and_package_lan.ps1" -SkipClient
powershell -ExecutionPolicy Bypass -File ".\Tools\export_and_package_lan.ps1" -SkipServer
powershell -ExecutionPolicy Bypass -File ".\Tools\export_and_package_lan.ps1" -NoTimestamp
```

输出目录：

- `Build/Packages/LAN-Package-时间戳/`
- 传 `-NoTimestamp` 时为 `Build/Packages/LAN-Package-latest/`

包结构：

- `Client/Debug`
- `Client/Release`
- `Server/`
- `README.txt`

## 手动冒烟基线

每次涉及入口、会话、渲染或多人流程的改动后，至少手动验证：

1. 主菜单能正常打开
2. `新游戏` 与 `继续游戏` 至少有一条链路可走通
3. 关键 HUD / 面板能正常显示
4. `自动化测试` 入口可达
5. 如果改到多人流程，至少验证大厅/房间入口不会立即失效
