# MiniRPG 涌现世界路线图

这份文档只回答一个问题：**在现有 Utility AI 基线之上，怎么让世界开始"自己长故事"？**

不展开 AI 理论教程；只描述 MiniRPG 的下一步目标、现有基线、以及"不要做什么"。其它决策见 [`重构路线图.md`](./重构路线图.md) 与 [`架构现状.md`](./架构现状.md)。

## 目标

从 "NPC 会自己过日子" 推进到 "世界会自己长事件"：玩家 2 小时游戏后会自然说出"因为发生了 X，所以这个区变乱了 / 那人变了"，而不是"NPC 会巡逻会吃饭"。

## 现有基线（第一层已基本到位）

MiniRPG 在"NPC 会自己过日子"这一层已经覆盖约 80%：

- 决策：`UtilityBrain.Evaluate` + `InputResolver`（~60 输入源） + `ResponseCurve`（6 种曲线） + 三层思考缓存（`UtilityCache`）
- 数据驱动：`Data/Config/utility_actions.json`（~27 个 Action 不改代码可调）
- 性格：`Data/Config/personality_defaults.json`（10 轴 + 种族/职业偏移）
- 行为执行：`Executors/` 按行为簇分七类（Need / Combat / Social / Survival / MentalBreak / Job / Idle）
- 感知输入：`AwarenessModule`（4 状态 FSM，只做 AI 输入）、`ThreatDetection.HasNearbyThreat`
- 持续状态：`GameState`、`Actors`、`WorldMap / ChunkData`；`Needs/*`；`thoughts.json`（带 `moodOffset` + `durationTurns` 的情绪痕迹）
- 玩法系统：战斗 / 医疗 / 手术 / 交易 / 种田 / 巢穴 / 心理崩溃

第一层剩下的"更多 Action"按需补即可，属于数据工作，不需要架构动作。

## 缺的四件事（第二层）

要让世界开始"自己长事件"，需要补这四件**小而内聚**的东西。顺序很重要，后一步依赖前一步。

### 第 1 步：`GameEventConsequenceRouter`（最高 ROI）

对称于已有的 `App/RuntimeUi/GameEventPresentationRouter`（后者负责 UI/FX/日志），补一层**系统消费端**：把 NPC 行为产生的 `GameEvent` 分发给治安、关系、经济等系统。

- 落点：`MiniRPG.Shared/Core/Events/GameEventConsequenceRouter.cs`（Shared 里，因为系统层不依赖 Godot）
- 约束：`GameEvent` 保持唯一事实流；消费端只读 + 触发后续 module 的方法，不要绕过 `ServerActionGateway` 直接改状态。
- 第一个示范后果链可选"偷窃事件"：触发 → 关系受损 + 治安紧张度 + 店主记忆。

### 第 2 步：`RelationshipModule`

持久化 `(actorA, actorB) → RelationshipState`，初始从派系 / 职业 / 亲缘推断，随事件增减。

- 落点：`MiniRPG.Shared/Core/Social/RelationshipModule.cs`，和现有 `SocialModule` 平级（`SocialModule` 是"社交动作执行器"，不是长期关系图）。
- 输出：新增一组 InputResolver（`RelationshipTrust<target>` / `RelationshipFear<target>` / `RelationshipDebt<target>`），让 Utility 评分因人而异，而不是仅对 `Factions` 三态做判断。
- 不要做：不要重做 `PartyModule` / `Factions`，它们回答的是"队伍 / 阵营归属"，关系图补充的是"个体对个体"。

### 第 3 步：`ActorMemoryModule`

每个 actor 有一个 bounded list 的 `Memory { subjectId, eventKind, strength, decay }`。关键事件写入（被偷 / 被救 / 被威胁 / 欠债）。

- 落点：`MiniRPG.Shared/Core/Social/ActorMemoryModule.cs`
- 复用：`thoughts.json` 已经有 `moodOffset` + `durationTurns` 的衰减语义，可复用一半结构；`Thoughts` 关心的是"我自己的情绪痕迹"，`Memory` 关心"我对 X 的事的认知"——两套存，别混。
- 输出：再一组 InputResolver（`MemoryFearTowards<target>` / `MemoryDebtOwedTo<target>` / `MemoryBetrayalBy<target>`）。

### 第 4 步：信息不对称（先只做一条：目击者 → 谣言）

加一个极简 `Rumor` 结构和 `RumorBus`：

```text
rumor { sourceEvent, content(带模糊描述), credibility, spreadRangeMeters, lifeTurns }
```

- 落点：`MiniRPG.Shared/Core/Social/RumorBus.cs` + actor 上新增一个 `NpcKnowledge`（"我听说过的 rumor 列表"）。
- 关键：**NPC 的 Utility 评分读 `NpcKnowledge`，不是全局真相**。有了这个字段，"误会 / 冤枉 / 偏见"才能自然产生。
- 不要做：一开始不要给所有 NPC 加 Knowledge；先让目击者、相关阵营成员、巡逻守卫有，其他人默认空。

### 可选第 5 步：治安 / 经济的事件反馈

等前四步跑通、且一组"会传播的后果链"上线，再考虑：

- `DistrictSecurityLevel`（按事件增加）→ 影响守卫 AI 的巡逻生成与盘查阈值
- `TradeModule.AdjustPriceOnEvent`（库存减少 / 抢劫 / 封路 → 价格微调）

这两项在前四步没打好底之前做是白做。

## 不要做的事

- **不要先上 GOAP**。`UtilityActionDef` 已经数据驱动，多步行为可以靠"上一个 Action 留下的状态 → 下一个 Action 评分变化"自然串联；GOAP 的 planner / 前置条件 / 回溯搜索会让维护成本飙升，先把状态回写做完再决定是否需要。
- **不要引入 LLM 驱动 NPC 决策**。延迟不可控、成本不可控、复现不可控。LLM 只适合"包装层"（把 `Memory` + `Rumor` 翻译成对白），决策还是走 Utility AI。
- **不要把 `NpcKnowledge` 合进 `GameState` 的全局读面**。每个 NPC 的知识是 per-actor 的，**必须可以和世界真相发生偏差**——否则"信息不对称"失效。
- **不要一次做 100+ 个 NPC**。30 个 NPC + 完整事件闭环 > 300 个 NPC + 没有后果传播。
- **不要把"包装层"和"世界模拟"混在一起**。数据结构只保留结构化字段（`eventKind` / `strength` / `decay`），对白和描述由模板层或后续可选 LLM 翻译。

## 完成判定

不用里程碑文档，用**玩家体感**作为完成标准：

| 阶段 | 判定句式 |
| --- | --- |
| 第 1 步完成 | 玩家能观察到 "A 发生之后 B 反应"（例：偷东西 → 巡逻加强） |
| 第 1-2 步完成 | 玩家会说 "那个人好像记仇" |
| 第 1-3 步完成 | 玩家能复述单个 NPC 的个人小史 |
| 第 1-4 步完成 | 玩家会说 "我误会了那个人" 或 "这个流言传开了" |
| 第 1-5 步完成 | 玩家会说 "这个街区气氛最近变了" |

玩家无法自然说出对应句式时，不算完成。
