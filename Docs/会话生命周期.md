# MiniRPG 会话生命周期

这份文档只回答一个问题：**一次会话切换，哪里负责清什么？**

不展开每个模块的实现细节，只列时机和清理契约。遇到具体代码落点看 [`架构现状.md`](./架构现状.md)。

## 会话切换的四个时机

| 时机 | 触发入口 | 典型场景 |
| --- | --- | --- |
| 新开局 | `GameSessionModule.NewGame` / `NewBlankEditorMap` / `StartWorldCharacter` | 主菜单 → 新游戏 / 角色创建完成 |
| 读档 | `GameSessionModule.LoadGame` / `LoadWorldCharacter` / `LoadPresetScenario` → `CommitPreparedLoad` | 继续游戏 / 世界管理面板进入 |
| 楼层切换 | `GameSessionModule.ChangeFloor` / `TryUseStairs` | 上 / 下楼 |
| 联机进入 | `GameSessionModule.ApplyMultiplayerRoomSnapshot` | 多人加入房间后首个快照到达 |

会话退出本身不走这里：主菜单按钮走的是 `MainAppFlowCoordinator.HandleBackToMenu`，触发的是"准备期的清理 + 自动 quicksave"，本身不会创建新会话。

## 清理契约

切换时的清理按**状态层 → 表现层 → 面板层**三层推进。任何绕过这三层的直接清理都是 bug。

### 状态层（`GameSessionModule` 内部，改 `GameState` 全局）

每次"新开局 / 读档 / 楼层切换"都会显式执行：

- `_state.Reset()` — 清空 `GameState` 全部子状态
- `_fogTracker.Clear()` — 迷雾重建
- `InitializeWorld(options)` 或 snapshot apply — 装载世界
- `TimelineTurnManager.Reset(_state)` — 回合/时间线
- `PartyModule.Initialize(_state)` — 组队
- `ActorDerivedStateUpdater.SyncAllActorsForSession(_state)` — 衍生状态一次性同步
- `ResetSessionContext(kind)` — 清 `CurrentSavePath` / `CurrentPresetScenarioId` / World+Character context

**不应由表现层代劳**：上述每一项都在状态层统一做掉，客户端不需要再 touch。

### 表现层（`Main.SessionFlow.cs` / 渲染器）

`FinalizeSessionPanels(openSkillBar)` 是 session 就绪后、面板就位前的收口，必须覆盖：

- 技能 / 武装 / 目标：`ClearArmedSkill` / `EndSkillTargetCursorMode` / `ClearPlayerTargeting`
- 自动寻路：`CancelAutoNavigation(AutoNavigationStopReason.SessionReset)`
- 世界工具：`ResetRuntimeWorldToolSession`
- 威胁 HUD：`ResetThreatHud`
- 渲染：`_mapRender?.ResetActorMotionState()` + `_mapRender?.ResetOverlays()`
- 设置 UI / 回合推进 UI / 角色视觉 / 音频：`SyncSettingsUiState` / `SyncTimelineAutoAdvanceState` / `RefreshPlayerCharacterVisual` / `OnSessionStartedAudio`

`DoEnterGame` 在 Finalize 之后跑，负责：

- `_multiplayerHub.Close` / `_menu.EnterGame` / `_inputModule.EnterActionMode`
- 再一次 `_mapRender?.ResetActorMotionState`（防竞态）
- `FlushMap()` 把首帧画出来

### 面板层

`FinalizeSessionPanels` 末尾会把以下面板复位：`_skillBar`、`_skillMgr`、`_inventoryPanel`、`_chestPanel`、`_dialogPanel`、`_tradePanel`、`_questPanel`、`_debugPanelController`、`_statusPanelController`、`_panels.ClearFocus()`。新增面板如果需要在会话切换时清理，就接到这里。

## 多人联机追加项

多人进入会话后，`MainAppFlowCoordinator` 仍走 `FinalizeSessionPanels` + `DoEnterGame` 两步，额外再做：

- `MultiplayerRuntimeCoordinator` 在收到首个 snapshot 时调 `_resetActorMotionState()`（对应一次 `_mapRender.ResetActorMotionState`）防止预测动画穿帮。
- `ClientPredictionState.Configure(config)` 重置预测队列、回滚计数、`NextClientTick`。

## 不做什么

- 不在渲染器 / 面板内部 `Clear()` 自己的缓存来"兜底修 bug"。
  表现层只跟状态层的 reset 走；渲染器自带缓存（如 `ChunkTerrainSurfaceCacheStore`）会在下一帧通过 `TerrainGeometryRevision` 自动失效。
- 不跳过 `_state.Reset()` 做"增量替换"。历史上出现过的状态污染都来自这类"增量"。
- 不让 UI 持久保存 `GameState` 的引用做加工。UI 缓存必须在 `FinalizeSessionPanels` 或 `DoEnterGame` 失效。

## 新增状态时的清单题

在状态 / 会话上新增一块字段或缓存前问自己：

1. 它是否属于 `GameState` 的子状态？→ 进 `_state.Reset()` 的收敛面。
2. 它是表现层缓存？→ 挂 `FinalizeSessionPanels` 或让其随 revision 号自动失效。
3. 它需要在读档时从 `SaveFile` 重建？→ 接到 `FinalizeLoadedGame` 的结尾处。
4. 它是否跨会话保留（例如设置项）？→ 那它**不属于会话生命周期**，放 `AppSettingsStore`。
