# MiniRPG 架构现状

这份文档只记录当前稳定边界和高频入口。
它刻意不展开全量 public type、全量调用链和全量目录树。

## 当前基线

- `App/Main.cs` 与 `App/Main.*.cs`
  - 仍然是 Godot 入口、场景装配点和组合根。
  - 方向是“变薄”，把运行时编排继续下沉到 `App/RuntimeUi/*`。
- `App/RuntimeUi/*`
  - 当前已经承接启动、输入、主流程、多人联机、运行时视图和事件呈现。
  - 关键类型包括 `MainStartupCoordinator`、`MainInputCoordinator`、`MainAppFlowCoordinator`、`Multiplayer*Coordinator`、`GameEventPresentationRouter`、`RuntimeViewCoordinator`、`MainRuntimeComposition`。
- `MiniRPG.Shared/Core/*`
  - 领域状态、世界、回合、AI、对话、交易、调试等核心逻辑所在。
- `MiniRPG.Shared/Module/*`
  - 会话编排、服务端指令、多人联机适配等应用层服务所在。
- `Module/Panel/*` 与 `Module/Render/*`
  - 本地 UI 面板框架和渲染实现所在。

## 当前稳定边界

### 入口与运行时编排

- `Main` 负责 Godot 生命周期、场景节点获取、组合根装配和少量薄委托。
- `MainRuntimeComposition` 把运行时依赖拆成服务、UI 引用和钩子三组。
- `GameEventPresentationRouter` 已经承担一部分 `GameEvent -> UI/FX/日志` 翻译，不再把所有副作用都塞回 `Main`。

### 会话与存档

- `GameSessionModule` 是当前会话生命周期入口。
- `WorldCatalogService` 负责世界/角色目录、摘要和删除。
- `ContinueStateService` 负责继续游戏目标解析与持久化。
- `MiniRPG.Shared/Module/Session/*`
  - 通过 `IGameSessionBackend` 区分本地与多人联机会话 backend。
- `IDebugSessionActions` 作为薄接口提供调试命令需要的会话动作，避免 `Core.Debug` 直接依赖 `GameSessionModule` 实现。

### 运行时事实源

- `GameState` 是唯一运行时事实源。
- `WorldMap` / `ChunkData` 负责格子、chunk 和世界空间真相。
- `Actor` 运行时数据由状态层维护，不把显示缓存当成真实状态。

### 指令与玩法执行

- `ServerActionGateway.Execute` 仍然是客户端指令统一入口。
- 当前已开始把非分发职责外提到专门服务，例如 `ReservationService`、`LootService`。
- 基于时间线的玩家动作通过 `TimelineTurnGateway` / `TimelineTurnManager` 一侧推进。

### 渲染与视图

- `TileMapRenderModule` 仍是当前 2D/2.5D 渲染组合入口。
- `FogOfWarTracker` 负责视野/战争迷雾语义。
- `WeatherFxController` 已经从渲染总控中抽出天气特效职责。
- `IsometricVoxelRenderer` 仍承担等距体素路径，是正在继续拆薄的热点之一。

## 主流程

### 启动

1. `Main` 进入 Godot 生命周期。
2. `MainStartupCoordinator` 与 `MainRuntimeComposition` 装配运行时服务、UI 和资源。
3. 会话、输入、面板、渲染和多人联机协调器接线完成后，进入主菜单或当前会话。

### 输入到命令

1. 输入进入 `InputModule`。
2. `MainInputCoordinator` / `GameplayCommandCoordinator` 负责把输入转换成游戏命令。
3. 命令按类型路由到会话层、面板层、本地玩法执行或多人联机协调层。

### 会话切换

1. 菜单、世界管理器或继续游戏入口触发会话动作。
2. `GameSessionModule` 编排新开局、读档、继续、楼层切换或多人联机会话切换。
3. 目录、继续状态和 backend 细节分别交给抽出的服务处理。

### 事件到表现

1. Core 侧产出 `GameEvent`。
2. `GameEventPresentationRouter` 把事件翻译为日志、面板状态、对话/交易 UI 和战斗特效。
3. 各 HUD、面板和 FX 系统按需刷新。

### 地图与视图刷新

1. `FogOfWarTracker` 先计算当前可见语义。
2. `TileMapRenderModule` 负责 TileMap、实体、地面物品和天气表现的组合刷新。
3. 2D 与 2.5D 模式在同一个渲染组合入口下切换。

## 当前热点

- `Main` 已经比早期结构更分散，但仍是重要收口点。
- `GameSessionModule` 正在朝“纯会话编排层”收敛。
- `ServerActionGateway` 仍有继续外提 handler/service 的空间。
- `TileMapRenderModule` 仍是渲染热点，后续应继续拆分 pass、模式切换和性能记录。

## 修改时先看哪里

- 启动、主菜单、运行时编排：`App/Main*.cs` 与 `App/RuntimeUi/*`
- 会话、继续游戏、世界目录、多人 backend：`MiniRPG.Shared/Module/GameSessionModule.cs`、`ContinueStateService.cs`、`WorldCatalogService.cs`、`MiniRPG.Shared/Module/Session/*`
- 玩法指令执行：`MiniRPG.Shared/Module/ServerActionGateway.cs`
- 渲染与视图：`Module/Render/TileMapRenderModule.cs`、`WeatherFxController.cs`、`IsometricVoxelRenderer.cs`
- 边界和批次目标：[`重构路线图.md`](./重构路线图.md)
