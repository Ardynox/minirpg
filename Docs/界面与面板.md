# 界面与面板

这份文档归纳玩家在游戏里能看到的所有 UI 元素：每个面板做什么、展示哪些字段、玩家能做什么操作、数据从哪来。
不是面板代码 API 展开稿，而是"改 UI 时必须先看一眼，避免改坏"的设计基线。

面板**实现入口**与焦点 / 布局 / 拖拽框架请看 [`../Module/Panel/README.md`](../Module/Panel/README.md)，这里只回答"有什么、显示什么"。

## 修改 UI 时的标准流程

1. 先在本文找到对应面板，确认它的**当前职责、字段、数据源、特殊行为**。
2. 改动如果只是字段微调（加一列、换文案、改样式），直接改对应 `*PanelModule.cs` 与本表的字段说明。
3. 改动如果涉及**新面板、新快捷键、新模态遮挡、改变 HUD 抑制规则、改变焦点行为**，必须同步更新本文 + `Module/Panel/README.md`，并在 PR 描述里说明。
4. 不要把面板显示缓存当成玩法事实——状态真相在 `GameState` / Core / Module 层；面板只展示与发命令。
5. 联机注意：面板里所有"改世界"的命令必须走 `IHost.TrySubmitClientCommand` → `ServerActionGateway`，不要在面板里直接 mutate `GameState`。

## 1. 框架基础（一段话）

- 所有可聚焦面板实现 `IPanel`（`Module/Panel/IPanel.cs`），统一暴露 `PanelId`、`PanelNode`、`Visible`、`HandleCommand(cmd)`、`OnFocus/OnBlur`、`Dirty/FlushIfDirty`。
- `PanelManager` 维护**焦点栈**：`PushFocus` 压栈、`Escape` 默认映射为 `"close"` 调用当前焦点面板的 `HandleCommand("close")`、关闭后从栈顶恢复上一个焦点。
- 列表型面板继承 `ListPanelBase` / 实现 `IFocusableListPanel`，自带行池、上下导航、PageUp/PageDown/Home/End。
- **布局持久化**写入 `user://panel_layout.json`：`PanelLayoutService` 应用尺寸 + 按钮缩放，`PanelDragService` 应用位置；运行时克隆面板（`runtime_status_*`）显式 `PersistPosition: false`。
- **HUD 抑制**：`Main.UiMode.cs` 的 `RuntimeUiModeSnapshot` 计算 `SuppressHudAndAlerts` / `BlocksGameplayInput` / `PausesGameplayLoop`；模态层、设置 Overlay、对话面板都会触发暂停。

## 2. 面板分类总览

按"玩家视角的可见行为"分组，**不是按继承关系**：

| 分类 | 谁属于这一类 | 共同特征 |
| --- | --- | --- |
| **常驻 HUD** | `PanelLauncherBar`、`TurnPanel`、`MapPanel`、`LogPanel`、`InputBar`、`PartyHud`、`NeedsHud`、`ThreatHud`、`TargetSummaryHud`、`HealthAlerts`、`IncidentAlert`、`TurnControllerPanel` | 会话进行中始终存在；多数不参与焦点；`SuppressHudAndAlerts` 时由主循环跳过更新 |
| **玩法面板（可拖拽，走焦点栈）** | `StatusPanel`(运行时克隆)、`InventoryPanel`、`SkillBar`、`SkillManager`、`ChestPanel`、`TradePanel`、`ConversationPanel`、`QuestPanel`、`ActorInspectPanel`、`LimbTargetPanel`、`GroundPanel`、`DebugPanel` | 有快捷键 / 启动条 / 事件触发；位置 + 尺寸持久化；Esc 关闭并弹栈 |
| **模态 / 阻断玩法** | `PauseMenuPanel`、`SettingsPanel`、`WorldManager`、`ConfirmDialog`、`SaveNameDialog`、`WorldSettingsDialog`、`CharacterCreation`、`LoadRecoveryDialog`、`MultiplayerRoomPanel` | 可见时 `HasVisibleModalLayer` 或 `SettingsOverlayVisible` 为真，玩法循环暂停、HUD 抑制 |
| **叠加层** | `ToastOverlay`、`RichTooltipLayer` | 不抢焦点；只显示瞬时信息，不接受键盘交互 |
| **工具条 / 编辑器式** | `LayoutEditBar` | 仅在特定模式下出现（布局编辑）；不属于常规玩法 |
| **调试用** | `DebugPanel`、`UIDevProbe` | 正式发布默认不暴露；`UIDevProbe` 只往控制台打日志，无 UI |

**布局可编辑的 PanelId**（`Main.cs::LayoutEditablePanelIds`）：`status, skill_bar, skill_mgr, inventory, ground, log, chest, conversation, trade, quest, debug, actor_inspect, limb_target`。新增可拖拽面板请加进这个列表。

## 3. 常驻 HUD

### 3.1 PanelLauncherBar — 顶部启动条

- **节点**：`HudLayer/UI/PanelLauncherBar`（`App/Main.PanelLauncher.cs`）
- **用途**：一行按钮，点击 toggle 主要面板的开关；按钮处于"已开"状态时高亮。
- **包含按钮**：状态 / 技能条 / 技能管理 / 背包 / 任务 / 调试 / 设置
- **每个按钮的 tooltip**：`<动作中文名> [<快捷键>]`，文案由 `InputBindingService.GetActions` 生成。
- **特殊行为**：`busyOperationActive` 或资源未就绪时整条禁用；按钮状态由 `RefreshPanelLauncherState` 根据各面板 `Visible` 同步。
- **不要做**：不要把它做成"主菜单"——主菜单是另一个层。

### 3.2 TurnPanel — 时间轴 / 回合状态条

- **类**：`Module/Panel/TurnPanelModule.cs`（**非 `IPanel`**）
- **节点**：`HudLayer/UI/TurnPanel`
- **展示**：阶段徽章、当前行动者名、`T:<世界回合>`、渲染模式文案、最多 4 个**队列芯片**（行动者名 + 行动条进度）
- **数据源**：`TimelineTurnManager.CreateDebugSnapshot`
- **操作**：纯展示，无交互
- **特殊行为**：固定单行高度，避免换行抖动

### 3.3 MapPanel — 地图视口

- **PanelId**：`map`（被动注册，`AllowGlobalClose: false`）
- **用途**：主视口；玩家移动 / 攻击 / 拾取的鼠标交互入口
- **特殊行为**：Esc **不会**关闭它；方向键会被 `PanelManager` 放行（`ShouldTrapDirectionalInput` 对 `map` 返回 false）

### 3.4 LogPanel — 事件日志

- **PanelId**：`log`（被动注册，`canFocus: false`）
- **节点**：`HudLayer/LogPanel`
- **用途**：滚动显示 Core 侧事件日志（战斗 / 拾取 / 死亡 / 任务 / 对话广播 / 系统提示）
- **特殊行为**：不可聚焦、不参与键盘命令；只在编辑模式下可拖动

### 3.5 InputBar — 命令输入

- **节点**：HUD 上的 `LineEdit`（不是 `IPanel`）
- **用途**：玩家输入 `:inventory` / `:render` 等命令字符串（见 `Main.Command.cs`）；快捷键 Enter / T 唤出
- **特殊行为**：进入命令输入会切换到 `Typing` 输入上下文，吞掉其他键

### 3.6 PartyHud — 队伍 HUD（左上）

- **类**：`Module/PartyHudModule.cs`
- **展示**：队伍成员列表，每行：成员名、HP 简示、心情简示，激活成员高亮
- **操作**：点击行切换激活成员；快捷键 `P` (`cycle_party`) 顺序切换
- **数据源**：`PartyModule`

### 3.7 NeedsHud — 需求 HUD（右上）

- **类**：`Module/NeedsHudModule.cs`
- **展示**：饥饿 / 口渴 / 休息 / 心情 标签 + 进度条，颜色按阈值变化
- **数据源**：当前激活成员的 `NeedsModule` 状态

### 3.8 ThreatHud / TargetSummaryHud / HealthAlerts / IncidentAlert — 战斗与告警

- **节点**：`OverlayLayer` 上代码创建（`App/Main.Startup.cs`）
- **用途**：战斗中显示威胁来源、目标摘要、HP 临界提示、突发事件提示
- **特殊行为**：`SuppressHudAndAlerts` 为真时（菜单 / 模态 / 玩家死亡 / 对话中等）由 `_Process` 跳过更新

### 3.9 TurnControllerPanel — 回合自动推进控制

- **类**：`Module/Panel/TurnControllerPanelModule.cs`（非 `IPanel`）
- **节点**：`OverlayLayer/TurnControllerPanel`
- **展示**：标题、`T:<回合>`、播放 / 暂停按钮、单步按钮、速度滑条 `×n`
- **操作**：`PlayToggled` / `StepRequested` / `SpeedChanged` / `CloseRequested`
- **数据源**：传入的 `turn` 与 `playing` 状态

## 4. 玩法面板（可拖拽，走焦点栈）

每个面板的**默认快捷键**取自 `Module/InputBindingService.cs::BuildDefaults`，玩家可在设置 → 控制 里改键。

**「操作 & 反馈」模板**：从 4.2 InventoryPanel 开始引入，目的是让"玩家每一种输入 → 即时反馈 → 提交的命令 → 失败 i18n key → 跨面板联动"在文档里可机器核对。模板有 5 栏，缺任何一栏都视为未写完：

- **输入**：左键单击 / 右键单击 / 左键拖拽 / 右键拖拽 / 键盘（列具体键）/ 数字键 / 双击 / hover
- **即时反馈**：高亮 / 焦点框 / 拖拽幽灵 preview / toast / 日志文案 / 音效 / Refresh 节奏
- **提交的命令**：`ClientCommand` 类型名 或 `TimelinePlayerAction` 或 `_host.*` 跨面板调用
- **失败 i18n key**：`log.xxx.*` 一看就知道拒绝时玩家看到什么（便于多语言排查）
- **跨面板联动**：触发 / 关闭 / 刷新哪些其他面板

按 `AGENTS.md` 的**触发式维护**：4.2 是已落地的完整范例；其他交互性面板在条目末尾放 `> TODO:` 占位，**下一次真正改到那个面板时**再按这个模板填实。不要现在做全量填充。

### 4.1 StatusPanel — 角色 / 尸体多页状态（运行时克隆）

- **类 / PanelId**：`StatusPanelModule` / 动态 `runtime_status_actor_<id>` 或 `runtime_status_corpse_<id>`
- **管理者**：`App/RuntimeUi/RuntimeStatusPanelController.cs`（基于 `Scene/StatusPanel.tscn` 模板克隆，每个目标一个面板，可同时多开）
- **打开方式**：
  - `H` (`toggle_status`) → 开关激活成员的状态面板
  - 顶部启动条 状态按钮
  - 鼠标查看 / 检视目标 → `OpenInspectTarget`
  - 查看尸体 → `OpenCorpse`
- **展示信息（页签）**：肢体、容量、标签、Buff、装备、需求、健康、家族、基因组（尸体模式无 Tab，只显示尸体头）
- **每页内容**：上方 `NameInfo` 头（玩家头 / 检视头 / 尸体头）、`ContentText` 多行、底部 `HintBar`（仅演员模式）
- **操作**：`up/down` 行滚动；`left/right` 或 `,` `.`（`status_prev` / `status_next`）切 Tab；`close`
- **数据源**：`GameState` + `Actor` 或 `Item`，文本由 `Module/Panel/ActorStatusTextBuilder.cs` 渲染
- **特殊行为**：克隆面板 `PersistPosition: false`（位置不持久化，避免开多个时叠在一起）；同位面板冲突时按 `RuntimeStatusPanelPlacementPolicy` 替换

### 4.2 InventoryPanel — 背包

- **类 / PanelId**：`InventoryGridPanelModule` / `inventory`（节点路径仍为 `TopRow/InventoryPanel`）
- **打开方式**：`I` (`inventory`) / 启动条按钮
- **数据源**：`ActorModule.GetPlayer(state).Inventory`（`Item.InstanceId` 作为引用 key） + `player.GridInventories`（多容器：pockets / backpack / vest / belt / holster）
- **展示信息**：
  - 顶栏摘要（重量、金币等，`RenderHeader`）
  - 装备纸娃娃：每个部位 3 个 layer strip（Shell / Middle / Skin，`BuildSlotCell` + `BuildLayerStrip`）
  - 主背包网格：`GridStack` 多容器拼接，每个物品按 `GridPlacement` 占 W×H 格（`BuildPlacementVisual`）
  - 右侧 `DetailBox` 详情（`ItemFormatHelper.BuildDetail` + 尺寸 + 可旋转提示）
  - 未放置物品提示 `UnplacedHint`（橙色条）
  - 底部动作栏：`[E]` 装备 / `[U]` 使用 / `[R]` 旋转 / `[Q]` 丢弃 / `[F]` 自动整理
  - **hover tooltip**：装备 layer / 网格物品都挂 `_tooltipLayer`，输出完整 `BuildDetail` BBCode

#### 操作 & 反馈

下表列出玩家每一种输入→即时反馈→提交的命令→失败路径。新增交互必须补进这张表。

| 输入 | 即时反馈 | 提交的命令 | 失败 i18n key |
| --- | --- | --- | --- |
| **左键单击 placement / 装备 strip** | `_selectedInstanceId` 记录；**释放时** `Refresh()` → 金色 border `(1,0.85,0.4,1)` + fill inset；`DetailBox` 更新；底部动作按钮按 category 启用/禁用，Equip 文案在装备/未装备间切换 | — | — |
| **右键单击 placement / 装备 strip** | `ShowContextMenu` 弹 `PopupMenu`，菜单项按 item 状态动态生成：Open（容器）/ Equip-Unequip / Eat（食物或 Nutrition tag）/ Rotate（可旋转且非正方形）/ Drop | 菜单项触发对应命令（见下） | 同对应命令 |
| **左键拖 placement → 空格** | `AttachDragPreview` 挂半透明幽灵；`_CanDropData` 返回 false 时 Godot 自动光标"禁止" | `InventoryMoveItemClientCommand { ActorId, ItemInstanceId, TargetGridId, X, Y, Rotated }` | `log.inventory.grid_error.{GridFull\|OverlapsExisting\|OutOfBounds\|RotationDisallowed\|GridNotFound\|ItemNotFound}`（由 `ServerActionGateway::ResolveGridErrorCode` 翻译）|
| **左键拖 placement → 装备 strip** | `CanDropOnEquipStrip` 前置校验 `item.BodyPart == slot.BodyPart && item.Layer == slot.Layer`；不匹配时光标"禁止" | `InventoryToggleEquipClientCommand` | `log.inventory.unequip_first` / `log.inventory.not_equippable`（视 `ServerActionResult.Logs`）|
| **左键拖 装备 strip → grid** | drag data 带 `source="equipped"`；`DropAtGrid` 先 `ToggleEquip` 卸下、再 `MoveTo` 落位 | `InventoryToggleEquipClientCommand` → `InventoryMoveItemClientCommand`（两条） | 同上 + grid 错误族 |
| **`R` 键** | Refresh，物品占格 W/H 互换 | `InventoryRotateItemClientCommand` | `log.inventory.grid_error.RotationDisallowed` |
| **`F` 键 / 自动整理按钮** | Refresh，物品重新紧凑摆放；成功提示 `log.inventory.grid_autopack` | `InventoryAutoPackClientCommand` | 同 grid 错误族 |
| **`[Q]` / Drop** | 物品出现在地面，面板刷新；GroundPanel 同步显示 | `InventoryDropClientCommand` | （无专门 i18n，失败路径走 gateway 通用错）|
| **右键菜单「打开容器」** | 关闭背包，打开 `ChestPanel` 显示该容器内容 | `_host.OpenChestFromInventory(item)`（跨面板调用，不是 ClientCommand）| — |

**反馈节奏契约（关键，别踩坑）**：
- 左键 **Pressed** 只更新 `_selectedInstanceId`，**绝不** `Refresh()`。press 时 `QueueFree` 会把 drag 源 Control 立即销毁，Godot 4 的 drag-drop 永远启动不了。
- 左键 **Released** 才 `Refresh()`（重建 grid + 装备 strip），让选中高亮在松手后出现；如果中途发生了 drag，Godot 直接走 `_DropData` 分支，不会再触发 release 的 gui_input，`Refresh()` 由 `DropAtGrid` 末尾统一负责。
- 右键 **Pressed** 立即 `ShowContextMenu`；Refresh 不需要。
- 任何命令提交后必须 `Refresh() + _host.FlushMap()`，保证 grid 和地图同步到权威结果。

**拖拽实现契约（别踩坑）**：
- `BuildPlacementVisual` 的 `container` **必须是 `DragDropControl`**（见 `Module/Panel/README.md` 的 Godot 4 drag-drop 常识段）。不能只让父 canvas 有 drag data——Godot 4 的 `_GetDragData` 不向父节点冒泡。
- `MouseFilter = Pass`：让 GuiInput（选中 / 右键菜单）走到 placement，同时拖拽也从 placement 自己的 `OnGetDragData` 启动。
- canvas 的 `GetDragDataForGrid` 只负责"点到空网格背景"这条兜底路径，不是主路径。

**跨面板联动**：
- 「打开容器」→ 关闭本面板 + 打开 `ChestPanel`（4.5）
- 装备变动 → 可能触发 `GameEventPresentationRouter` 更新 HUD / 地图角色贴图（见 `App/RuntimeUi/EquipmentSpriteOverlay.cs`）
- Drop → `GroundPanel`（4.11）显示新物品

### 4.7 ConversationPanel — 对话

- **类 / PanelId**：`ConversationPanelModule` / `conversation`（**懒加载**：`Scene/DialogPanel.tscn`）
- **协调器**：`ConversationUIModule`（`Module/Conversation/`），把 `GameState.ActiveConversations` 同步到面板
- **展示信息**：标题（NPC 名 + mood 图标）、正文、选项行 `[n]` 文案；技能检定分支会附带 `DC` 与估算成功率

### 5.4 捏脸流程（CharacterCreation → CharacterCustomizationPanel）

- **入口**：`CharacterCreation` 主面板里 `CustomizeRow/CustomizeBtn`。
- **数据模型**：`MiniRPG.Core.Data.FaceCustomizationData`（8 个部件 id + 4 个颜色 + 1 个 `MapSpriteTemplateId`）。**单一数据源**：UI / 持久化 / 渲染 都从这一份读。
- **目录数据**：`MiniRPG.Core.Data.FacePartCatalog` — 8 类部件目录（HeadShape / Eyes / Eyebrows / Nose / Mouth / Ears / Hair / Beard），从 `Data/FaceParts/*.json` 加载，缺失时走内置 fallback。
- **肖像合成**：`App/RuntimeUi/PortraitComposer.cs` + `ProceduralFacePartRenderer.cs` 把 `FaceCustomizationData` 按层叠顺序合成到 256×256 `Texture2D`（用 Godot.Image 程序化绘制，几何 helper 在 `App/RuntimeUi/GodotImageGeometry.cs`，与地图 sprite 路径**共享**），结果按 `ComputeCacheKey` 缓存。
- **地图 sprite 合成（玩家）**：`App/RuntimeUi/MapSpriteRuntimeFactory.cs` 接受 `FaceCustomizationData + EquipmentAppearanceData`，按 `CharacterGeometryProfiles` 描述的体型 / 发型 / 胡须 / 耳朵 / 角形状程序化画 64×64 base human canvas → 8 方向投影成 256×2048 sheet → 缓存 `ImageTexture`。装备（武器 / 披风 / 头盔 3 大件）由 `EquipmentSpriteOverlay.Project(actor)` 从 `actor.Inventory` Equipped 项投影，叠加在 base canvas 上一起投影。`Module/Render/IsometricVoxelRenderer.TryResolveActorSpriteVisual` 玩家分支直接调它，**绕过 `entity_render.json` 静态条目**。
- **地图 sprite（NPC + 怪物）**：仍走 `Data/entity_render.json` + `MonsterMapAssetGenerator` 程序化生成的 8 方向 PNG。怪物 / 玩家两条 sprite 路径共享 `Tools/CharacterSpriteUtilities.cs` 的几何 helper + 8 方向投影管线，视觉风格天然统一。
- **离线 fallback PNG**：`Tools/BaseHumanSpriteGenerator.cs` 通过 `dotnet run -p Tools/MonsterMapAssetGenerator -- generate-humans` 生成 `Assets/Art/Generated/character_map_iso8/base_human_default_8dir.png`，作为 `entity_render.json` 里 `player` / `human` entry 的 fallback texture（玩家 actor 还没设 FaceCustomization 时用）。
- **预览**：
  - `CharacterCreation` 主面板预览框：左侧「合成肖像」（PortraitComposer 输出），右侧「地图 sprite 单帧」（MapSpriteRuntimeFactory 南方向那一帧，与玩家在地图上看到的视觉完全一致）。
  - `CharacterCustomizationPanel` 自己的预览框只显示合成肖像；用户改完点「应用」回灌到主面板。
- **NPC 外观**：`PresetDB.SpawnActor` 在每个 actor spawn 时按 `instanceId` hash 用 `FaceCustomizationData.CreateRandom` 派生稳定随机捏脸数据写入 `actor.FaceCustomization`，让玩家 inspect 任何 NPC 时都能看到合成肖像。
- **存档 round-trip**：`SaveSnapshot.SavePayload.PlayerFaceCustomization` + `ActorSnapshot.FaceCustomization` 双向序列化；缺失时 `ResolvePlayerFaceCustomization` 返回新 default。
- **`CharacterCustomizationPanel` 模态注册**：已加入 `Main.Startup.cs` 的 `_modalInputLayers` 数组，`Main.UiMode.cs` 的 `hasVisibleModalLayer` OR 链也已加入（参考 8.4 节两侧同时维护规则）。
- **不再存在的中间层**（2026-04-19 大清扫删除）：`PlayerAppearanceCatalog` / `MapSpriteTemplateCatalog` / `LegacyAppearanceMigration` / `legacy_presets.json` / `MapSpriteResolver` / `character_color_mask.gdshader` / `state.PlayerAppearanceId` 字段。捏人系统现在**只有单一管线**：`FaceCustomizationData → PortraitComposer + MapSpriteRuntimeFactory`。

## 8. 全局规则

### 8.1 Escape / 关闭键

- 默认 `Escape` 走 `panel_close`（焦点面板时 `HandleCommand("close")`）或 `open_settings`（无焦点面板时打开暂停菜单）。
- `MapPanel` 的 `AllowGlobalClose: false`：Esc 不会关闭它。
- 暂停菜单和设置面板都 `ConsumeUnhandledKeys: true`：避免误触发玩法快捷键。

### 8.2 焦点栈

- 用 `PanelManager.PushFocus` 打开面板，栈顶为当前焦点；关闭后弹栈到上一个。
- 鼠标点击聚焦走 `FocusFromPointer`，会保留焦点历史。
- 面板从外部被关闭时必须调用 `OnPanelClosed`，否则栈会泄漏。

### 8.3 布局持久化覆盖范围

- **存**：宽高、按钮缩放（`PanelLayoutStore`）+ 拖动结束的位置（`PanelDragService`，仅 `PersistPosition: true`）
- **不存**：运行时克隆的 `runtime_status_*` 面板的位置（避免多开叠加冲突）
- **编辑模式才可动**：`ground` / `log`（`RegisterEditModeOnly`）
- **常驻可动**：`inventory` / `skill_bar` / `skill_mgr` / 懒加载面板（`RegisterAlwaysDirectDraggable`）

### 8.4 HUD 抑制

`Main.UiMode.cs` 的 `RuntimeUiModeSnapshot` 是判定真相：

| 状态位 | 触发条件（任一为真即触发）|
| --- | --- |
| `BlocksGameplayInput` | busy / 主菜单 / 布局编辑 / 地图编辑 / 模态层可见 / 对话面板可见 |
| `SuppressHudAndAlerts` | 上述任一 + 玩家死亡 + 未开局 |
| `PausesGameplayLoop` | busy / 各类模态对话框 / 多人房间 / 地图编辑 / 布局编辑 / 设置 Overlay / **对话面板可见** |
| `AllowPanelChrome` | busy / 布局编辑 / 地图编辑 / 模态层 全为假 |
| `AllowPanelDrag` | busy / 地图编辑 / 模态层 全为假（布局编辑下可拖） |

**新增模态面板必须做两件事**：
1. 实现 `IModalInputLayer` 并在 `Main.Startup.cs` 注册进 `_modalInputLayers`（让键盘输入正确路由）。
2. 在 `Main.UiMode.cs` 的 `hasVisibleModalLayer` 计算式里把它的 `IsXxxOpen` 加进 OR 链（让 HUD 抑制和玩法暂停生效）。
两步漏一步都会出 bug：只做 1 → 模态层显示了但游戏循环还在跑；只做 2 → 游戏暂停但模态层不接键盘。

## 9. 鼠标悬停信息框（tooltip）规范

游戏里"鼠标停一会弹小信息框"的体验需要在所有高频信息密度位置普及。
基础设施已经有了——`Module/Panel/RichTooltipLayer.cs`（单例挂在 `OverlayLayer`，BBCode 富文本，0.25s 延迟，自动避开屏幕边缘）。
本节回答：**什么时候用、写什么、怎么挂、不该加在哪**。

### 9.1 三种 hover 信息框，怎么选

| 场景 | 用什么 | 例子 |
| --- | --- | --- |
| UI 控件、需要富文本 / 多色 / 多字段 / 运行时数据 | `_richTooltips.Attach(control, factory)` | 物品行、技能格、buff 徽章 |
| UI 控件、纯文本短提示（按钮名 + 快捷键） | Godot 原生 `Control.TooltipText` | 启动条按钮、工具条按钮 |
| 地图格子（地形 / 实体 / 物品 / 人物） | 已有 `WorldHoverOverlay`（`App/Main.MapAndCamera.cs`） | 选择模式下 hover 地图 |

**禁止 UI 控件用 `WorldHoverOverlay`**：那是世界坐标专用的，不该跨界。

### 9.2 tooltip 内容字段约定（按控件类型）

- **物品行**：完整名称（经 `IdentificationModule.GetItemDisplayName`）/ 重量 / 价格 / 栈数 / 装备状态 / 耐久 / 完整属性词条与描述（直接复用 `MiniRPG.Shared/Module/Panel/ItemFormatHelper.cs::BuildDetail(state, item)`，是所有物品面板共享的 BBCode 详情来源；`Item` 模型本身没有 `Description` / `Quality` 字段）
- **技能格 / 技能行**：复用 `Module/Panel/SkillTooltipBuilder.cs::BuildSkillDetailBbcode(skill, actor, state, armedSkillId)`——名称（按分类着色）/ 分类 / armed 或 cooldown 状态 / power / cooldown / range / 伤害类型 / 描述 / 需求 / 容量需求 / 来源（装备 / 天生）
- **Buff / Debuff 徽章**：名称 / 剩余回合（永久标 `permanent`）/ Buff Tags 列表
- **标签徽章**：tagKey 本地化名 / 当前 value
- **装备槽**：当前装备走 `ItemFormatHelper.BuildDetail`；空槽给出"该穿什么类型"
- **队伍成员行**：完整 HP / 心情 / 位置 / 种族
- **需求条**：精确数值 / 警告阈值 / 状态描述（饥饿 / 饥渴等阶段）
- **肢体行**：部位名 / 耐久比 / 要害 / 缺失 / 严重受损 / 受伤 / 良好 状态描述
- **按钮**：动作中文名 + 当前绑定快捷键（用 `App/Main.PanelLauncher.cs::BuildActionTooltipBbcode` 模板，输出 `[b]名[/b] [color=#888][键][/color]`）

### 9.3 最小代码模板

```csharp
_richTooltips.Attach(button, () =>
    $"[b]{skill.Name}[/b] [color=#888]{skill.Category}[/color]\n" +
    $"伤害 {skill.Damage} · CD {skill.Cooldown}\n" +
    $"[color=#ccc]{skill.Description}[/color]");
```

颜色优先用 `Module/Panel/UIColors.cs` 已有常量或 `Data/UI/design_tokens.json`，**不要硬编码新色值**。

### 9.4 列表面板（ListPanelBase）的特殊处理

- 行池复用：每次行内容刷新时**重新调 `Attach`**，会覆盖旧 factory，不必先 Detach
- 行容器 `TreeExiting` 时 `RichTooltipLayer` 自动 Detach，无需面板主动清理
- factory 是闭包：必须**捕获当前行的数据快照**而不是行索引（行索引在排序 / 过滤后会变）
- 推荐落点：`RowStyleHelper` 之后、行点击事件绑定之前

### 9.5 生命周期与协作

- 控件销毁由 `TreeExiting` 自动清理
- 同一控件多次 `Attach` → 自动覆盖 factory（参考 `Module/Panel/RichTooltipLayer.cs` 的 `Attach` 实现）
- factory 内部对 `GameState` / `Actor` / `Item` 必须 null check（联机断线 / 切换会话瞬间数据可能为 null）
- tooltip 是纯客户端展示，不发命令、不参与多人联机协议、不需要会话生命周期清理

#### 9.5.1 注入约定：`ITooltipRegistrar`

面板 / HUD 模块拿到 `RichTooltipLayer` 实例的统一通道是 [`Module/Panel/ITooltipRegistrar.cs`](../Module/Panel/ITooltipRegistrar.cs)：

```csharp
public interface ITooltipRegistrar
{
    void RegisterTooltips(RichTooltipLayer layer);
}
```

约定：
- 实现方在方法内**只持有 layer 引用**（如 `_tooltipLayer = layer`），不立即 Attach
- 真正 `Attach` 在 `Refresh` / `RebuildRows` / `ApplyRowContent` 等**渲染落点**调用
- `_tooltipLayer` 字段类型为 `RichTooltipLayer?`，所有 Attach 调用走 `_tooltipLayer?.Attach(...)`，让 layer 未注入时面板正常工作（测试 / 早期初始化场景）

`Main` 在 `BindSceneTreeNodes` 末尾创建 `_richTooltips` 后：
- `InitializePanelsAndChrome` 末尾调 `RegisterPanelTooltips()`，`TryRegisterPanelTooltip(panel, _richTooltips)` 给所有实现接口的常驻面板 / HUD（背包 / 地面 / 技能条 / 技能管理 / 队伍 / 需求 / 状态模板）批量注入
- 懒加载面板（`Ensure*Panel`：宝箱 / 交易 / 肢体目标 等）在创建后单独调 `TryRegisterPanelTooltip`
- `RuntimeStatusPanelController` 构造函数接收 `RichTooltipLayer?`，每个克隆 `runtime_status_*` 面板创建时单独 `module.RegisterTooltips(...)`
- 启动条 `BindPanelLauncherRichTooltips()` 单独走一条 wire-up 路径（不实现 `ITooltipRegistrar`，按钮直接挂 factory）

### 9.6 优先级清单 / 已接入状态

下表是项目当前实际接入了 hover tooltip 的控件类与对应模块。新增面板 / HUD 时按"是否进入这张表"判定要不要补 tooltip。

| 优先级 | 控件类 | 涉及面板 | 状态 |
| --- | --- | --- | --- |
| P0 | 物品行 | `InventoryGridPanelModule`（背包，含 layer strip + grid placement）、`GroundPanelModule`、`ChestPanelModule`、`TradePanelModule` | 已接入 |
| P0 | 技能格 / 技能行 | `SkillBarModule`、`SkillManagerModule`（共用 `SkillTooltipBuilder`） | 已接入 |
| P1 | Buff / Debuff / 标签徽章 | `StatusPanelModule` 的 Buff / Tag Tab（重构为逐项 `Label` + tooltip） | 已接入 |
| P1 | 装备槽 | `StatusPanelModule` 的 Equip Tab（重构为逐项 `Label` + tooltip） | 已接入 |
| P1 | 队伍成员行 | `PartyHudModule.PartyMemberSlot` | 已接入 |
| P1 | 需求条 | `NeedsHudModule`（4 条 `ProgressBar`，注册时改 `MouseFilter=Stop` 才能收 hover） | 已接入 |
| P1 | 肢体行 | `LimbTargetPanelModule` | 已接入 |
| P2 | 启动条按钮 | `Main.PanelLauncher.cs::BindPanelLauncherRichTooltips`（7 个按钮，factory 闭包动态读 `_inputBindings`） | 已接入 |

### 9.7 不要加 tooltip 的情况

- 主区域已用大字体完整展示的字段（`StatusPanel` 正文、详情 Box）
- 玩家右键 / 双击 已能打开详情面板的——不要再 hover 重复同样信息
- 模态确认按钮、主菜单按钮（文案已明确）
- 一闪而过的 toast 类提示（本身就是临时的）

### 9.8 不要做的实现反模式

- 不要在 factory 里执行重计算（每次 hover 都会调用一次）；如需聚合，缓存到面板字段
- 不要把 BBCode 颜色硬编码进字符串字面量；走 `UIColors` / `design_tokens.json`
- 不要在 tooltip 里放可点击控件——`RichTooltipLayer.MouseFilter = Ignore`，不接收输入
- 不要给同一个控件同时设置原生 `TooltipText` 和 `RichTooltipLayer.Attach`（`Attach` 会清空原生，但混用易混淆）
