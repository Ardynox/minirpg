# 角色美术风格参考（2.5D 顶视 8 方向）

> 生成：2026-04-19
> 目的：给「程序化几何 baseline → 最终角色视觉」之间架一组**具体可对标的游戏 + 可复用的 prompt 关键词**，作为后续 Banana 出图、shader 调色、装备分层叠加的视觉锚。
> 适用范围：玩家 / NPC / 非怪物人形角色的 map sprite（不覆盖怪物，怪物已有自己的 monster_map 总表）。

---

## 0. 前置事实（先看清楚再用参考）

| 事实 | 当前值 | 影响 |
|---|---|---|
| 角色生成方式 | 程序化几何（`Tools/BaseHumanSpriteGenerator.cs`） | baseline 是几何色块，不是 AI / 手绘 |
| 单格规格 | 256×256，8 方向 vertical sheet | 排除立绘、横版、3D 第三人称参考 |
| 视角 | 顶视 3/4 等距（与 Banana 总表 §0.2 对齐） | 排除纯俯视 / 纯侧视游戏 |
| 整体风格基线 | grounded semi-realistic, muted, soft overcast | 排除 anime / chibi / cartoon / 高饱和 |
| 可配置维度 | 8 部件 id + 4 颜色 + map sprite 模板 id | 参考要能覆盖：脸部、发型、胡须、装备 4 个维度的可叠加性 |
| 当前调色板 | skin `#E8C4A2`、hair `#604026`、cloth `#765838`、pant `#523A26`、belt `#462E1C` | 棕色系土色已锁，参考主要解决「细节密度 + 笔触 + 装备清晰度」 |

**所以「找参考」要回答的具体问题不是"想要什么风"，而是：**

1. 256×256 顶视 3/4 角色，怎样在「不糊成一团」和「不堆细节堆成 AI 海报」之间取平衡？
2. 装备 overlay（剑、盾、衣、帽）单独绘制后叠到 base body 上，业内典型做法是什么？
3. 程序化几何 baseline 后续往「半写实 + 笔触感」推，是靠 shader、是靠 AI 重绘 base，还是靠手 K 一套 base？

## 1. 顶级匹配（直接对标，建议优先看视频/截图）

### 1.1 Stoneshard（Ink Stains Games, 2020）
- **为什么对标**：top-down 3/4、棕调暗色、painterly 像素 hybrid、单角色能看清装备和面部细节，整体生存感强、不华丽
- **要借什么**：装备叠加的清晰度（武器/盔甲/披风都能在 sprite 上读出来）；脸部细节用极少像素表达（眉毛 + 鼻梁阴影即可建立辨识度）
- **不借什么**：它的暗调阴影偏重，本项目阴天柔光基调要更亮一档
- **关键词**：`top-down rpg, painterly pixel, low-saturation earth tone, equipment-readable silhouette, dark fantasy survival`

### 1.2 Wartales（Shiro Games, 2023）
- **为什么对标**：等距 + 中世纪 + 旅团生存 + 实用风装备 + 暖棕色调
- **要借什么**：实用主义装备表达——不是奇幻华丽，而是「补丁、磨损、皮带、布料褶皱」这种生存感
- **不借什么**：3D 模型的阴影逻辑（本项目是 2D sprite，不能搬全套 PBR 细节）
- **关键词**：`isometric medieval mercenary, weathered leather and cloth, muted earth palette, practical no-fantasy-bling`

### 1.3 Battle Brothers（Overhype, 2017）
- **为什么对标**：装备分层叠加最经典的实现之一——head / body / weapon / shield 全部独立绘制再合成，玩家能从 sprite 一眼看出全套配置
- **要借什么**：**装备 overlay 的分层组织方式**（这正是本项目 8 部件 + 4 颜色 catalog 要做的事）
- **不借什么**：它是侧视半身像，不是顶视全身，**视角不可参考，只参考分层逻辑**
- **关键词**：`layered equipment sprite, modular character composition, brigandine and chainmail, gritty mercenary aesthetic`

## 2. 高度匹配（参考某一面，不是整体）

### 2.1 Children of Morta（Dead Mage, 2019）
- **借**：top-down 等距 + painterly 像素，角色装备叠加好看，**比 Stoneshard 更鲜亮一档但仍然不饱和**——本项目色调可以靠这一档
- **不借**：奇幻气氛、神秘符文、家族奇幻调

### 2.2 Eastward（Pixpil, 2021）
- **借**：HD-2D painterly 像素的「笔触感 + 高质感低分辨率」——这是 painterly shader 后处理可能能逼近的目标
- **不借**：暖色调灯光、剧情向的 cinematic 镜头

### 2.3 Death Trash（Crafting Legends, 2021 EA）
- **借**：top-down pixel + painterly 暗调 + 装备 readable，世界感肮脏、实用、低饱和
- **不借**：Cult/horror 主题氛围

## 3. 辅助参考（看一眼即可，不要直接当模仿目标）

## 4. 角色专项 prompt 关键词包

> 在 Banana 总表 §0.2 风格基线之后追加这一组，针对 8 方向角色 sprite 微调。

### 4.1 正向词（追加在主题之后）
```
top-down 3/4 RPG character map sprite, single full-body figure standing in idle pose,
modular equipment-ready silhouette, readable from afar at 64x64 zoom,
hand-painted shading with visible soft brush strokes, low-saturation earthy palette,
worn practical clothing, leather and rough cloth textures,
clear separation between head / torso / arms / legs for layered equipment overlay,
neutral overcast lighting from above, subtle ambient shadow at feet only
```

### 4.2 反向词（在 §0.2 HARD NEGATIVES 之外再加）
```
no anime face, no chibi proportions, no oversized weapons, no shoulder pauldrons larger than head,
no rim light, no ground shadow casting outward, no dynamic action pose,
no perspective foreshortening, no ground texture, no environment props,
no multiple views in one image, no turnaround sheet, no character sheet, no UI labels
```

### 4.3 8 方向 sheet 专用补充（如果一次出 sheet）
```
output as a vertical sprite sheet, 8 rows, each row is the same character facing
S, SE, E, NE, N, NW, W, SW from top to bottom, identical pose and lighting in all rows,
exact 256x256 per cell, transparent background, perfect pixel alignment
```
> 现实警告：**Banana 一次出 8 方向稳定对齐基本不可能**。8 方向 sheet 仍建议走程序化 + AI 增强 baseline 的混合路线（见 §6）。

## 5. 与现有调色板的对齐建议

不要让 AI 自己决定颜色，**先把当前 baseline 调色板写进 prompt 当锚**：

```
strict palette anchors:
- skin base #E8C4A2 highlight #F2D6B0 shadow #8C6046
- hair base #604026 shadow #301E12
- cloth base #765838 shadow #3C2A1A
- trousers base #523A26 shadow #2C1E13
- leather belt #462E1C
do not introduce new hues outside this palette
```

这样后续 AI 出的「升级版 base human」能直接和现有几何 baseline 共存，不会出现「捏人预览是棕色、地图上跑出来变成米色」。

## 6. 推荐的下一步（可执行候选，不强制做）

按"离最终可玩更近一步"的标尺排序：

### A. 最快出效果（1 天内）
- 给当前 `base_human_default_8dir.png` 套一个 painterly post-process shader（参考已有的 `painterly_*.gdshader` 系列），让程序化几何也带上笔触感
- 不改生成代码，只在 Godot 端加 shader 材质
- **决策标尺 Y**：直接让玩家看到的角色变得不那么「Excel 色块」

### B. 中等投入（2-3 天）
- 用 §4 的 prompt 在 Banana 出 1 张「面南 idle」的 256×256 base human，作为 ground truth
- 将这张图与程序化 8 方向 sheet 的「面南那一格」做并排对比
- 决定后续 8 方向是「AI 出 8 张分别对齐」还是「AI 出 1 张 + 程序化旋转/翻转补其他 7 方向」
- **决策标尺 Y/N**：如果 AI 出图能对齐就 Y，对不齐就只是技术验证（N）

### C. 大投入（一周以上）
- 决定走「AI 出 base + 程序化 overlay 装备」还是「全手绘 base + 全手绘装备 atlas」
- 这是 cursor-opus-2.5d-figure 批 4「分层绘制」的前置决策，**建议等他批 1-3 完工后再做这个决定**
- **决策标尺 N（暂时）**：现在做这个会和 WIP 撞，先不动

## 7. 不该做什么

- **不要现在就开始大规模出图**：cursor-opus-2.5d-figure 还在动 base 生成器和 entry point，先等他这个批次稳定
- **不要新增 Docs/ 文档**：风格锚点已经在 `Assets/Art/README.md` §2 / Banana 总表 §0.2，只要本文件作为补充对标即可
- **不要把这份文件当成最终风格**：它是参考清单，最终风格只有「进游戏跑起来好看」才算定
- **不要让 AI 在 8 方向之外发挥**：所有候选必须能落到 256×256 顶视 3/4，否则就算图本身好看也接不进来
