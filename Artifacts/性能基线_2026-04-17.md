# MiniRPG 性能基线（2026-04-17）

> **触发**：批次 4（渲染层拆分）的目标是 `IsometricVoxelRenderer` 单类 < 1500 行，但当前 2233 行。拆分决策应基于**实测数据**而不是"看起来太长"。本文记录如何采样 + 当前基线 + 目标阈值。

## 现有采样基础设施

仓库里已经存在的测量能力，不需要新写：

- `Module/Render/RenderPerfTracer.cs` 每帧记录 frameTimeMs / spriteCount / drawCommandCount / editorViewActive / 可选 trace sample。
- `IsometricVoxelRenderer.LastPerfSnapshot`（`RenderPerfSnapshot { ActiveSpriteCount, DrawCommandCount, FrameTimeAvgMs }`）由 `Main` 的 `DebugPanelController` 读取后转交给 `DebugPanel` 展示。
- Godot 自带：`Performance.Monitor.*`（见 Godot 官方性能分析器）—— 不用修改本仓库代码即可打开。

## 采样流程（建议）

1. **冷启动 → 进入默认新游戏** → 等 3 秒稳定。
2. 打开 debug panel（`:debug` 或 HUD 按钮），记录如下数值的**峰值 + 5 秒平均**：
   - `FrameTimeAvgMs`
   - `ActiveSpriteCount`
   - `DrawCommandCount`
3. 做 3 组代表性场景采样：
   - **A. 静态俯视**（玩家站原地不动，相机默认 zoom）
   - **B. 快速平移**（长按 WASD 横穿 1 个 chunk）
   - **C. 集体战斗**（用 `:newmap` 刷新到敌多/天气明显场景）
4. 每组记 30 秒内 2 次采样，求中位数。

## 目标阈值

- **FrameTimeAvgMs**：目标 < 16.6 ms（60 FPS），上限 < 33 ms（30 FPS）。战斗场景允许临时短暂 > 16.6，但 5 秒平均不能超 33。
- **DrawCommandCount**：目标 < 2000，上限 < 4000。超了要优先合批 / instancing。
- **ActiveSpriteCount**：目标 < 5000，上限 < 8000。超了要拆渲染 pass 或降 LOD。

## 当超标时优先拆什么

只在**有数据支持**的前提下拆。下面是按"最可能是瓶颈"排的候选：

1. 如果 `FrameTimeAvgMs` 超标但 `DrawCommandCount` 正常 → CPU 端 hot code。查 `RenderPerfSnapshot.TraceSample` 里的 per-pass timing（若已实现）；没有的话先在 `IsometricVoxelRenderer.Render` 里插 `Stopwatch` 给每个 pass 计时，找出最慢的一个 pass 拆出去。
2. 如果 `DrawCommandCount` 超标 → 合批机会。拆 `TerrainAtlas` / `VoxelTilePathResolver` 的 draw 调用，检查能否用 MultiMesh。
3. 如果 `ActiveSpriteCount` 超标 → 远处 actor / 特效没剔除。检查 `FogOfWarTracker` 是否真正控制了可见性、`WeatherFxController` 粒子密度。
4. 如果三个都正常但玩家体感卡 → 不是渲染问题，查 Utility AI `Tick` / `ChunkManager.UpdateLoadedChunks` / 存档 I/O。

**在没有实测数据前，不做批次 4 的结构性拆分**——纯粹因为行数多去拆是"代码美化"，违反决策标尺第 0 条。

## 这份文档什么时候更新

- 首次采样填好三个场景的 baseline 后。
- 每次批次 4 拆分动作前后各跑一轮采样，把"前后对比"附在 commit 描述里。
- 如果 baseline 大幅变好/变坏（>20%），说明有别的改动影响了渲染路径，值得单独调查。

## 不做的事

- 不引入新的 profiling 库（Godot 自带够用）。
- 不改 `IsometricVoxelRenderer` 现有采样代码——避免和正在跑的渲染进程冲突。
- 不把这份文档搬进 `Docs/`——它是阶段性基线，属于 `Artifacts/`。测量方法稳定成"长期约定"后再考虑。
