## 三、新发现（按严重度排序）

### HIGH

#### H1. `revival_failed` + `conversation_*` 事件在 LogModule 完全未翻译

- **证据**：`App/RuntimeUi/GameEventPresentationRouter.cs:169-185` 已有对 Conversation 各类事件的分支；但 `Module/LogModule.cs:140-168` `ToLogLines` switch 对 `revival_failed`、`conversation_opened/advanced/chosen/closed/observer_joined/takeover_*` 全部落 `_ => null`。
- **影响**：复活失败（`ReviveService.cs:185` 明确发此 event）无任何 UI / 日志反馈；对话开启 / 选择 / 接管审批 在日志里完全静默，玩家事后无法追溯"刚刚发生了什么对话"。
- **修法**：补 LogModule switch；`conversation_rumor`（`ConversationModule.cs:345`）连 Router 也没接，需要 Router + LogModule 同补。

#### H2. 死亡报告 i18n key 全部缺失

- **调用证据**：`App/RuntimeUi/PlayerDeathPresenter.cs:73` `death.party_wiped`、`:81-88` `death.report.cause` / `death.report.recent_count`、`:96-110` `death.cause.killed_by / killed / incapacitated / blood_loss / infection / food_poisoning / unknown`。
- **落地证据**：`Data/I18n/zh_CN.json:651-658` 只到 `death.back_to_menu`；`en.json` 同段（约 707-714）同样缺；全仓 grep `death.party_wiped|death.report|death.cause` → 0 matches in `Data/I18n/`。
- **影响**：中文玩家死亡报告面板显示的是英文 fallback（`"Cause: {cause}"`、`"Killed by {killer}"`），破坏 L10n 基线；而死亡报告是《产品愿景》"结果可追溯"的核心 UX。
- **修法**：在 `Data/I18n/zh_CN.json` + `en.json` 的 `death.*` 段补 11 条 key（1 heading + 2 report.* + 8 cause.*）。最小修复 5 分钟。

#### H3. `ClientCommandRouter` 未实例化（Δ-1）

- **证据**：全仓无 `new ClientCommandRouter(`；`Main.Timeline.cs:158-177` 的 `TrySubmitClientCommand` / `SubmitClientCommand` 仍自己做多人 / 单机双轨决策。`App/RuntimeUi/ClientCommandRouter.cs:18-62` 的 `Submit` 方法是孤儿代码。
- **影响**：`Docs/多人联机契约.md:19` 把 `ClientCommandRouter` 描述为"统一入口"，与代码事实持续不符。**两种选择**必须选一：
  - **A**（改代码）：在 `App/Main.Wiring.cs` 构造期 `new ClientCommandRouter(_log, _sessionBackend, () => IsMultiplayerSession)`，把 `TrySubmit/Submit` 委托过去，在 `MultiplayerRuntimeCoordinator` 就位后调 `AttachMultiplayerRuntime`。`Main.Timeline.cs` 的 `TrySubmitClientCommand / SubmitClientCommand` 变成薄转发。
  - **B**（改文档）：改 `Docs/多人联机契约.md` 写"路由由 Main + Coordinator 共同决策"，并删除 `ClientCommandRouter.cs`（因为它变成纯废代码）。

#### H4. `ServerActionGateway` 继续臃肿（Δ-4）

- **证据**：887 行，33 个 `private static ExecuteXxx`。Chest / Trade / Conversation 全部内嵌。
- **影响**：分发逻辑越来越难审查。新加一个系统（本次的 Conversation 就加了 5 条 execute 分支）就往里塞。
- **修法**：按路线图批次 3：优先外提 `ChestHandler`、`TradeHandler`、`ConversationHandler`。每个 handler 实现 `IServerActionHandler { bool CanHandle(ClientCommand); ServerActionResult Execute(GameState, ClientCommand); }`，Gateway 只做 kind → handler 的注册/分发。

#### H5. `AutoTest` 抽样主角用 `GetPlayer`（Δ-5）

- **证据**：`App/Main.AutoTest.cs:81` `CaptureAutoTestSnapshot` 内 `ActorModule.GetPlayer(_state)`。

- **修法**：一行改 `ActiveActorAccess.GetActive(_state)`。风险低。
