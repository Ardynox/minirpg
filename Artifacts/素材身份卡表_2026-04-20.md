# MiniRPG 素材身份卡表（2026-04-20）

> 配合 `Artifacts/素材需求清单_2026-04-20.md` 使用。清单回答"需要什么"，身份卡回答"每一张的身份 / 落盘位置 / 结构约束"。  
> **重要原则**：本表**只写身份和结构**，不写视觉描述——所有"长什么样"的审美判断交给 Gemini 现场决定。每个批次开头有一段"风格咨询清单"，发包时先让目标进程问 Gemini 拍板本批风格，再按身份卡逐条出图。

> **链路与差异（2026-04-21）**：全局风格锚点见 `Artifacts/style_locks_B0.md`；各批子锁登记见 `Artifacts/style_locks_registry.md`；与当前代码/文件名不一致处见 `Artifacts/素材身份卡_运行时映射补充_2026-04-21.md`。

## 0. 通用结构 & 身份卡格式

### 0.1 身份卡字段

每条身份卡都是一行，列全：

| 字段 | 含义 |
|---|---|
| `id` | 稳定 id，对齐 `Data/*.json` 里现有的 `id`（没有数据源的单独注明） |
| `目标文件名` | 落盘时的精确 PNG 文件名（大小写、下划线严格对齐） |
| `目标路径` | 相对仓库根的完整路径，包含目录 |
| `画布` | `W×H`，PNG 透明度默认 alpha=0（天气/品牌等另注） |
| `上下文` | 这张图**在游戏里做什么用**，一句话；只写"是什么 / 什么情绪 / 什么场景"，不写"画成什么样" |
| `系列对齐` | 它要和哪些图同风格一起看（例如"同属 need 阶段图标系列"） |

### 0.2 发包流程（每个通道拿到一批后按此执行）

1. 先打开本批的"风格咨询清单"，把那几个问题贴给 Gemini，让 Gemini 给出本批的视觉指令（线稿 vs 扁平色、主色 vs 情绪色、是否角标、是否统一边框、是否留 pad、是否贴同一张 style reference……）。记在 `Artifacts/style_locks_<batch>.md`。
2. 按身份卡逐条发：**发主体身份 + 画布结构约束 + "与上面 style_lock 一致"**即可。不重复写视觉描述。
3. 落盘时严格按"目标路径"落；不要改名。
4. 如果 Gemini 漂风格，贴回 `match the exact style, palette and lighting of the previous image`。

### 0.3 统一硬约束（所有批都遵守）

- 文件名只有小写字母、数字、下划线，不要空格 / 中文 / 大写
- `.png.import` 一律**不要**由生成进程写，Godot 会自己补
- 单张 ≤ 5 MB；超过就在 Godot 里降质
- 默认透明底；只有天气/品牌/地表有底色的场景才允许
- 整张图一条资产，不要拼盘，不要 contact sheet
