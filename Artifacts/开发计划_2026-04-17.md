> **目标**：在 4 个 mcp 通道（qtwx-mcp-1/2/3/4）并发的前提下，把游戏从"技术原型"推到"玩家能连续玩 1 小时有代入感"。
> **决策标尺**：每条任务都必须能回答 [`../Docs/产品愿景.md`](../Docs/产品愿景.md) 的第 0 条"这个改动离最终可玩更近了吗？"。
> **口径**：本计划放 `Artifacts/`；每个 Sprint 结束时**新开一份带日期的后续版**，不覆盖旧版。上一版里完成的条目在新版里标记"已完成"后可删。

### 赛道边界的硬规则

1. 跨赛道的改动必须先在 `Artifacts/wip.md` 登记一行；否则视为违反协作纪律。
2. Main.*.cs 和 Panel 模块是**唯一长期独占赛道**——开工前先抢夺。一次只能一个通道动它。
3. 其它赛道可并行；冲突面基本只落在 Tests（接口变化传递到 fake）——由 F 赛道统一收口。
4. Shared/Core 新增公开 API 要通知 B/C 赛道主责，让他们后续接入时知道有这个入口。

### S1-2【A 赛道】B9 Cooking "地图默认摆灶台"最小 MVP ✅ 2026-04-17 完成

（原本计划降级，后又调研发现可做，实际完整落地）

- **本轮产出**：
  - `FacilityConstructionModule` 新增公开 API `TryPlaceCompleted(state, facilityDefId, anchorX, anchorY, z, rotation, ownerDomainId)`：**直接创建 `FacilityStage.Active` 的 facility**，跳过蓝图→送料→施工。专供地图初始化 / debug / 特殊 incident。正常玩家走 `TryPlaceBlueprint` 不变。
  - `MapGenModule.SpawnPlayer` 最后调用新方法 `PlaceStarterFacilities(state)`：
    - 在玩家周围 6 个候选 offset 依次尝试摆一个 `stove`（已存在的 FacilityDef，`tags: ["cooking", "heat"]`）。
    - 挂一张默认 `cook_simple_meal` bill（target 5 份、allowPersonal + allowDomain）。
    - 找不到合适位置静默跳过（降级到靠 starter kit 撑）。
  - `MapGenModule.GiveStarterKit` 依然扩充到 meal × 2 + water × 2 + bedroll + raw_meat × 2 + berries × 2，作为"生存第一天" + "做第一顿饭的原料"双保险。
- **当前局限**：`cook_simple_meal` 要 `cook` 职业（见 `Data/recipes.json`）。玩家默认职业若不是 cook 则需要先有带 cook 职业的 NPC 加入队伍才会启动 bill。可在后续 Sprint 通过"wanderer_join incident 偶尔生成带 cook 职业的 wanderer"或给 BillDef 加 `IgnoreProfessionRequirement` 字段解决。
- 验收：编译通过；新开局后 `state.Facilities` 包含一个 stove (Active) + 一条 bill；Jobscheduler 会为之生成 ProduceRecipe ticket。
- 决策标尺 0：Y（生存闭环"raw_meat + berries → meal_simple → 吃"整条链路打通）。

## 风险 & 止损

- **风险 1：Panel 重构继续延长**。如果 S1-5 做不了，S1-1 / S1-3 / S1-4 不受影响（它们不依赖 Tests），继续推进 Shared/Core 改动即可。
- **风险 2：Main 瘦身反复回滚**。不强求 B 赛道完成；A 赛道的所有接入点都走 `MiniRPG.Shared/Module/Session/*`（用户态级 API），不硬绑 Main 内部方法。
- **风险 3：性能真的是瓶颈但没采样**。S3 前必须采样一次，否则 D 赛道停工避免盲拆。
- **风险 4：代码行数增长但玩家感知没同步提升**。每个 Sprint 结束前要做"可玩 30 分钟"自测，答不出决策标尺 0 的任务要降优先级或砍掉。

## 调度建议给用户

- 每周一：你发一次"本周赛道分配"到每个通道，指定主责。
- 每日结束：各通道在 `wip.md` 更新自己当天的动过的文件 + 明天要动的文件预告。
- 周五：做一次 Sprint 回顾——完成了什么、撞了几次、下一个 Sprint 怎么调整。
- 发现撞车（两个通道同改一个文件）：立刻仲裁，后动的让先动的。
